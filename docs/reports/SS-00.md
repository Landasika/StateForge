## 为什么要先做这个

后面所有分析都要有一个能跑的真靶。这个靶不能依赖数据库或文件，否则
问题会从“Session 依赖”跑偏成“环境问题”。

所以这里做了一个很小的 Flask 应用，只使用 Flask 自带的签名 Cookie
Session。它足够真实：登录请求写 Session，后续请求通过 Cookie 带回来。
也足够小：所有行为都能用测试说清楚。

## 靶长什么样

| 路由 | 行为 |
|---|---|
| `POST /authenticate` | 口令正确时写 `session["uid"] = 7`；否则 403，不写 |
| `GET /protected` | 读 `uid`；为空 401，否则进入目标块 |
| `GET /protected_truthy` | 用 `if uid:` 判断 |
| `GET /protected_membership` | 用 `"uid" in session` 判断 |
| `GET /protected_subscript` | 用 `session["uid"]` 直接取 |
| `POST /logout` | `session.pop("uid", None)` |
| `POST /clear` | `session.clear()` |
| `POST /noise` | 写 `session["other"] = 7` |

目标块用函数标记，真实 `BlockID` 由 ProgramIR 给出，不在分析器里硬编码。

## 适配层做了什么

`fuzz_target.py` 是 Atheris 和 Flask 之间的薄适配：

- `target(data)` 接收一个请求 dict，或者一整段 `{"steps": [...]}`；
- 请求里的 `cookie` 字段会被忽略，不能靠伪造 Cookie 解锁目标；
- `reset_state()` 新建 test client，清空 Cookie Jar 和命中记录；
- `input_scope()` 让一次输入内的多个请求共享同一个 client；
- `observe_session()` 只读解码 Cookie，不建请求上下文、不触发路由；
- 观测状态分 `absent / decoded / invalid / unknown` 四种。

## 测试

```bash
python -m pytest stateforge/tests/targets/session_gate/ -q
```

结果：`14 passed`。

覆盖了：

- 匿名访问返回 401，目标块没有被 Trace 覆盖；
- 合法登录后同一个 client 能进目标；
- 非法口令不写 Session；
- 只写 `other` 不能进目标；
- `logout` / `clear` 后不能进目标；
- 两个 client 不共享 Session；
- 一次输入成功、下一次空输入不能借用上一次的 Cookie；
- `/noise`、`/logout`、`/clear` 即使返回 200，也不算目标覆盖；
- 伪造的 Cookie 被忽略；
- 三种守卫变体各算各的，不互相冒充。

## 这批判定不了什么

这批只证明靶和输入边界是对的。

它不证明静态分析能找出 Session 依赖，也不证明 Fuzzer 能自己拼出登录
序列，更不证明运行时条件已经验证。这些是后面几批的事。
