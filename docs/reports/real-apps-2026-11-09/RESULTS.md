"未解释转移"= 运行时相邻、静态图上既无直连边也无法经单个合成节点两跳解释的
转移,是诚实的残差指标。

### linkding 的 +1 是图缺陷,不是回填造成的

唯一一条新增未解释转移是 `root.py` 第 18 行的
`return redirect_with_query(request, reverse(...))`。静态图把这个 return
表达式里两个调用的求值顺序串成了 `returnsite::2 → callsite::1`,而运行时外层
调用返回后直接进 exit。也就是说**表达式链顺序在"return 嵌套调用"这一情形下
建错了**,动态边只是把它暴露出来。数量级极小,未修。

### 未解析事件的主体是模块级/类体执行

linkding 2325 条事件中 1879 条未解析、healthchecks 4225 条中 3302 条未解析,
看起来比例很高,但构成是:

| 应用 | `<module>` | 类体(`Meta`/`Form` 等) |
|---|---|---|
| linkding | 1111 | ~200 |
| healthchecks | 2463 | ~250 |

CFG 层只为函数建块,模块级和类体执行本来就不建模。这是结构性已知限制,
应看"未解析调用点"而不是"未解析事件"。

## 3. 跑测试跑出来的 5 个真缺陷

全量测试在基线提交(`2479351`)上是 **981 通过 / 0 失败 / 7 跳过**。
在本次工作前的代码上有 **11 个失败**。逐个追下去,全部是真缺陷,已修:

### 3.1 分层违规(`analysis` → `runtime` 向上引用)

`analysis/dynamic/callgraph.py` 导入了 `stateforge.runtime.tracer`。修法不是
登记例外,而是让动态层只依赖一个 `TraceRecord` 协议(四个字段的结构化类型),
不依赖运行时具体类。

### 3.2 预置语料被误判成"上一轮的结果"(3 个测试)

`run_epochs` 加的空目录守卫用"目录里有任何文件"判断,把调用方**故意预置**
的 `epochs/spool` 冠军种子当成了旧结果。`entry_driver` 里同样的守卫还把
`out/spool` 直接列进了产物清单。

两处都改成认**跑完才会写的标识文件**(`run_identity.json` /
`driver_identity.json`)。这两个文件都是在检查之后才写的,所以既不会漏判
真·旧结果,也不会误伤预置输入。

同一处还有 `lf_corpus.mkdir()` 丢了 `exist_ok=True`,预置空语料目录时直接
`FileExistsError`,已恢复。

### 3.3 URLconf 视图按短名猜,导致路由张冠李戴

`django_adapter._view_ref` 在 `(别名, 成员)` 查不到时,退化成"全项目按函数名
搜,取第一个命中"。linkding 的 `from bookmarks.views import bundles as
bundles_views` 里,别名 `bundles_views` 不是文件名,于是
`bundles/<int:bundle_id>/edit` 被记成了 `bookmarks.py:238` 的 `edit`。

后果是同一个 `(文件, 函数名)` 出现两条不同路由,目标推导判为歧义 → 拒绝 →
约束为空 → 执行阶段 `plan["segment"]` 为 None → `PlanSegment(**None)` 崩。

修法是**按该 URLconf 的导入表解析别名**成完整模块路径;短名退化只在全项目
唯一时接受,否则返回 None(宁可拒绝也不猜)。修复后
`bundles/...` 正确指向 `bundles.py:84`,healthchecks 的同名多路由从 11 降到 5。

### 3.4 微基准真值过期

`test_micro_static_and_dynamic` 的 `multiple_calls` 真值要求从 `first()` 返回后
重新进入宿主块 `run:2:block`,但静态图里只有 `returnsite::1 → callsite::2`,
**没有** `returnsite::1 → block::1`。旧 mapper 多吐的那次块命中是不可解释的
假命中,新 mapper 抑制它是更忠实的行为。修正的是真值文件,不是实现。

## 5. 已知限制

* `fava` 是**拷贝安装**到 site-packages 的,分析和轨迹过滤都必须指向
  `.venv/.../site-packages/fava`,否则一条项目内事件都留不下。这一点很容易
  踩,已写入 `drivers.md`。
* 各应用覆盖块比例都很低(最少的 realworld 55/739 = 7.4%,最高的 fava
  613/3995 = 15.3%),所以单次回填收益有限。动态回填是随覆盖率累积生效的。
