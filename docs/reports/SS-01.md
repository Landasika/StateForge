## 范围与实现

- 统一入口 `extract_session_accesses(source_dir, ir=None)` 产出
  `SessionAccess`：`site_id`、`block_id`、`source_file/line/col`、
  `operation`、`key_kind/key_expr`、`value_expr`、`effect_status`。
- 支持形式：
  - `session['k'] = v`（只记 SET，不重复记 READ）；
  - `x = session['k']` / `session.get(k[, default])`；
  - `'k' in session` / `'k' not in session`；
  - `session.pop(k[, default])`（READ + DELETE，保留 default 是否出现）；
  - `del session['k']`；
  - `session.clear()`（ANY，不伪造具体 key）；
  - `session.update({'k': v})` / `dict(k=v)`（按常量 key 拆分）；
  - 动态 mapping update / 未知 Session 方法（显式 UNKNOWN，不静默漏掉）；
  - `session['k'] += 1`（READ_MODIFY_WRITE）；
  - `session.setdefault(k, v)`（READ + SET）；
  - 动态 key（SYMBOLIC，保留表达式）；
  - `from flask import session as sess`、`import flask` /
    `flask.session`、简单局部别名；
  - 参数/局部变量遮蔽 `session = {}` 不误判。
- 作用域遍历不进入嵌套函数/lambda，避免同一访问重复计数。
- `site_id` 由源码位置 + 操作 + key 哈希，稳定且同一行多访问唯一。
- 有 ProgramIR 时按源码行绑定真实 `BlockID`；无 IR 时仍保留源码锚点。
- 所有静态事件 `effect_status="STATIC_MAY"`，不进入 verified 桶。
- 保留旧 `analyze_session_access()` 返回 `semantic_model.StateAccess` 的
  兼容路径；新入口 `extract_session_facts()` 与旧事实模型通过适配器同源，
  不另建第二套 session 事实协议。
