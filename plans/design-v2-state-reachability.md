## 1. 问题重定位(最终版)

**一句话**:优化代码覆盖率;手段是朝**未见过的状态**定向探索——深层代码被状态门控,新状态解锁新代码区域,覆盖是状态前沿推进的战果。

**thesis(三句)**:

> ① 深层代码被应用状态门控(认证门后的 handler、载荷存储后的使用分支、工作流下游端点)——盲 fuzzer 与代码覆盖制导 fuzzer 的覆盖曲线在这些门前**平台化**。
> ② 按代码 sink 定向(Predator 系)也不是答案:它需要先有漏洞报告才知道往哪打,且状态靠人工预置(原文 "providing the crawler with valid credentials"),自认状态显现的错误可能漏检。
> ③ 状态空间的前沿(未到达的状态)本身就是方向:**朝新状态定向,不需要任何先验报告**;每开一扇状态门,门后的代码区域随之解锁,覆盖上升是可测的后果;注解 sink 是路上的 oracle,不是方向盘。

**地图**:导航底座 = **代码层执行流图**(端点→处理函数→基本块 + 数据流),状态以**锚点**钉在图上(SA-PR 的 file:line 就是钉子);"CFG 恢复到执行流图" = 静态恢复 + 运行时校准(Predator 补边思想)。SSTG = 该图投影到端点粒度的粗视图,供规划器排链。

**goal 的两个来源**:①**状态前沿**(主):模型中未访问的状态原子/迁移 → 自动派生开门链;②注解位点(辅,漏洞验证场景):给定报告时验证之。

**形式化(论文 §3)**:

```
导航底座:G_xfg = 执行流图(代码节点 + 执行边 + 运行时校准边)
状态锚点:anchors ⊆ G_xfg × V(状态读写/守卫的代码位置;SA-PR 提供)
前沿:     F = 未访问的状态原子 ∪ 未执行的安全相关迁移
方向:     dist(s, F) —— 朝前沿的状态图/锚点距离(能量调度与链规划共用)
覆盖:     C(t) = 代码覆盖曲线 —— 随前沿推进而抬升(报告的主指标)
检出:     Reach(sink) ∧ Violation(Φ) —— sink 在探索路径上被路过时由注解 oracle 判定
SSTG:     G_xfg 的端点粒度投影(规划器排链用粗视图)
```

**佐证**(已实测):M4 二阶实验——逐输入恢复 MISS、epoch(n=4) DETECT(检出 = 使用点 oracle × 状态链);规划器 10/10(链构造可行性);快照恢复 ~0.7ms 深度无关(状态重置经济性)。

## 2. 状态空间定义(五维,按存储位置)

| 维 | 内容 | 生命周期 | 观测 | 控制 | 处置 |
|---|---|---|---|---|---|
| ① 会话/令牌态 | authed-as、角色声明、CSRF nonce | 一条链 | /me 类端点 | 客户端持凭据(θ) | **建模**(补 Session.role) |
| ② 持久数据态 | 行存在性、枚举字段、单向标志、**存储的污点载荷**、所有权 | 到还原止 | GET 读回 | 动作写 + L2 模板 | **建模**(补污点值变量) |
| ③ 配置态 | GUARDS/vulnerable/debug | 进程一生 | 静态可见 | 变体选择 | **建模**(入图为锚点) |
| ④ 进程内存态 | 全局变量、缓存、连接池 | 一个 epoch | 运行时可观测(插桩) | fork COW 整体回滚 | 不建模、声明控制权 |
| ⑤ 文件系统态 | 应用写出的文件 | 到还原止 | — | L2 模板扩展 | v2 |

边界句:"建模一切静态可恢复的状态,重置其余一切。" 前沿 F 主要是 ①②③ 的原子与迁移。

## 3. 方法总图(v2.1)

```
        ┌────────── 语义状态恢复(创新1)──────────┐
        │ AST 候选 → LLM 标注 → 选择器 → 状态锚点 │
        │    + 代码执行流图 G_xfg(静态+运行时校准) │
        └──────┬─────────────────────┬───────────┘
   前沿已知部分 │                     │ 前沿未知部分(模型缺口)
        ┌──────┴────────┐      ┌─────┴─────────────┐
exploit │ 规划器:朝未访问 │ explore: fuzzer        │
        │ 状态排开门链    │ 朝新状态变异探索         │
        └──────┬────────┘      └─────┬─────────────┘
               ▼  一条链 = 一个 epoch  ▼
        执行层:fork COW + L2 模板(创新3)
               ▼
        ① 新状态读回 → 前沿推进 + 补图(runtime-verified)
        ② 代码覆盖上升 ← 门后区域解锁(主指标)
        ③ 路过 sink → ANOTA 注解 oracle 判定(战利品)
        ④ 卡住(前沿不推进) → LLM 修理(假设,执行终裁)
```

**信号分层**:方向信号 = **状态前沿距离**(罗盘);报告指标 = **代码覆盖率**(战果);辅助信号 = 新颖度(新状态即前沿推进本身,与方向统一了);oracle = 注解(不掌舵)。

## 4. 三创新点(v2.1 终稿)

1. **语义状态恢复**(Security-Relevant State Recovery):候选锚定标注(静态候选 + 六类枚举标签 + 确定性选择)+ 模型生命周期(运行时校准;前沿停滞 → LLM 补边假设,执行终裁,入审计日志)。
2. **新状态定向的状态空间探索**:以**未见状态**为导航目标(区别于:代码覆盖制导的盲积累、代码 sink 定向的报告依赖、Atropos 的无方向积累);exploit(规划器排开门链)与 explore(fuzzer 朝新状态变异,参数词汇=分支字面量)统一于同一前沿;覆盖随门解锁上升 = 可测主张。
3. **状态感知快照调度**:检查点位置 = 状态评分(安全相关性/距前沿 + 前缀复用 + 重建成本 + 新颖度);四策略消融。

## 6. 评测设计(v2.1)

**主图**:代码覆盖曲线(时间轴)——主张:B0/B1 平台化于状态门,B2 持续爬升;配状态覆盖曲线(前沿推进)与门解锁事件标注。
**主表**:逐漏洞类 TTD / requests-to-detection / 检出数 / 误报(注解目标作为验证性 eval)。
**消融**:−规划器(纯 fuzzer 探索)/−状态定向(退化为代码覆盖制导=接近 B1)/−LLM 修理/快照四策略。
**指标**:代码覆盖率(主)、状态覆盖数、TTD、restores/s、规划/绑定成功率、LLM 调用与成本。
**基线**:B0 裸 Atheris;B1 ANOTA+Atheris(注解 oracle + 代码覆盖,凭据预置=Predator 同款公平);B2 全家。
**靶场**:vulnshop(+ 注解门控 RCE sink)、VAmPI、DSVW;第四靶在议。
