## 1. 问题重定位

**目标漏洞类**:认证后 RCE、二阶(存储型)漏洞、越权链、工作流绕过——共同特征:**必须在特定应用状态下才可触发**。

**核心命题(thesis)**:

> 代码距离 ≠ 状态距离。二阶漏洞的使用点在每个请求中执行(代码距离≈0),真正远的是状态前置:载荷须先持久化、认证须先建立。按代码距离定向的 fuzzer(Predator 系)把能量灌在"接近目标代码"的输入上,而这些输入恰恰到不了所需状态;深层 Web 漏洞深在**状态空间**,不在代码空间。

**佐证**(已实测):M4 二阶实验——逐输入还原 MISS、epoch(n=4) DETECT,检出 = 使用点 oracle × 状态链;Predator 原文自述凭据人工预置("providing the crawler with valid credentials")且承认状态显现的错误可能漏检。

**形式化(论文 §3)**:

```
S = 状态空间(V 的取值集;V = 安全相关状态变量投影)
a: S ⇀ S   (一次 HTTP 请求 = 状态上的部分转移函数)
B ⊆ S     (漏洞区域 = 状态门 × sink;或非法迁移)
d(B)      = 从 S₀(检查点)到 B 的最小动作数 = 深度
检出 ⇔ Reach(B) ∧ Violation(Φ)   —— 二阶乘积律的实验回声
SSTG = S 的 AND/OR 可导航投影;规划器 = 路搜索;epoch/检查点 = S 的回滚
```

## 2. 状态空间定义(五维,按存储位置)

| 维 | 内容 | 生命周期 | 观测 | 控制 | 处置 |
|---|---|---|---|---|---|
| ① 会话/令牌态 | authed-as、角色声明、CSRF nonce | 一条链 | /me 类端点 | 客户端持凭据(θ 绑定) | **建模**(补 Session.role) |
| ② 持久数据态 | 行存在性、枚举字段、单向标志、**存储的污点载荷**、所有权 | 到还原止 | GET 读回 | 动作写 + L2 模板 | **建模**(补污点值变量) |
| ③ 配置态 | GUARDS/vulnerable/debug | 进程一生 | 静态可见 | 变体选择 | **建模**(入 SSTG 为原子) |
| ④ 进程内存态 | 全局变量、缓存、连接池 | 一个 epoch | 静态不可见 | fork COW 整体回滚 | 不建模、声明控制权 |
| ⑤ 文件系统态 | 应用写出的文件 | 到还原止 | — | L2 模板扩展 | v2 |

边界句(论文台词):"**建模一切静态可恢复的状态,重置其余一切。**"

两类示例在空间中的位置:
- **认证后 RCE**:B = {Session.authed_as=∀ ∧ ③ 允许} × sink 位点;链 = register→login→sink。
- **二阶漏洞**:污点值变量(如 Comment.text,域=载荷空间);B = {载荷已存储 ∧ 请求到达使用点},且两请求须同 epoch(M4 实证)。

## 3. 方法总图

```
        ┌──────────── 静态状态恢复(创新1)────────────┐
        │ AST 候选 → LLM 语义标注 → 确定性选择器 → SSTG │
        │ 模型生命周期:恢复 → 运行时校准 → LLM 修理    │
        └───────┬──────────────────────┬─────────────┘
          已知图 │                      │ 缺口(coverage-gap/卡住)
        ┌───────┴────────┐      ┌──────┴──────────────┐
exploit │ 规划器:状态距离 │ explore: fuzzer:状态新颖度 │
        │ 定向,链直达已知 │      │ 反馈;参数词汇=分支   │
        │ 目标态          │      │ 字面量(借 Predator) │
        └───────┬────────┘      └──────┬──────────────┘
                ▼  一条链 = 一个 epoch  ▼
        执行层:fork COW 检查点树 + L2 模板恢复(创新3)
                ▼
        判定:ANOTA 注解 = 目标规格 + violation oracle
                ▼
   回流:新状态原子→补边/新目标 · 违规→Finding · 卡住→LLM 修理
```

**五角色分工**:静态分析出**结构与候选**;LLM 出**语义**(标注)与**假设**(修理),永不做决策(ADR-0009);规划器 **exploit** 已知图;fuzzer **explore** 模型外状态(反馈=状态新颖度);ANOTA 注解**定义目标并判违规**;快照使一切**可重置、可重复**。

**关键机制:状态新颖度反馈**。代码覆盖回答"代码去没去过";状态覆盖回答"状态空间去没去过"。epoch 末读回观测 → (var,value) 与 SSTG 已知原子求差 → 新原子 = 种子奖励 + 补边(runtime-verified)+ 检查点候选(SF5 N_state 项的数据来源)。

## 4. 三创新点(终稿)

1. **语义状态恢复**(Security-Relevant State Recovery):候选锚定标注(静态候选 + 六类枚举标签 + 确定性选择器)+ **模型生命周期**(运行时校准;卡住判据 = coverage-gap 非空 / 状态距离不降 / 无新状态 → LLM 补边假设,执行终裁,提案入审计日志)。
2. **状态空间定向与探索**:规划器按**状态图距离**定向(区别于一切代码距离定向);fuzzer 以**状态新颖度**为反馈探索未知状态;explore/exploit 由同一张 SSTG 统一;fuzz 只变异参数区(链结构由规划器保证)。
3. **状态感知快照调度**:检查点位置 = Score(S) = α·security_relevance(距目标图距离) + β·hit_rate(前缀复用) + γ·1/(1+rebuild_cost) + δ·N_state(新颖度,来自反馈环);四策略消融(root-only/static-auth/random/scored)。

## 6. 评测设计

**基线阶梯**(同一预算 = 每 goal 300 请求/10 分钟):
- **B0** 裸 Atheris(无注解无状态)
- **B1** ANOTA+Atheris(注解 oracle + 代码覆盖;**凭据预置**——与 Predator 同款公平设置)
- **B2** StateForge 全家(状态恢复 + 规划 + 新颖度反馈 + 快照)

**消融**(B2 减单项):−规划器(纯新颖度探索)/−新颖度反馈(仅代码覆盖)/−LLM 修理 / 快照四策略(SF5)。

**指标**:逐漏洞类 time-to-detection、requests-to-detection、检出率、FP、状态覆盖数(新原子数)、restores/s、规划/绑定成功率、LLM 调用数与成本。

**靶场**:vulnshop(受控,含**新增:注解门控 RCE sink 端点**——认证后 RCE 行的数据来源;已批准默认加入,移除零成本)、VAmPI(外部)、DSVW(二阶)。第四靶场待议(风险项)。

**预期主张**:B1 检不出状态类(工作流绕过/二阶/认证后 RCE——链不可达);B2 检出且 TTD 显著短;新颖度反馈在"模型有缺口"靶(VAmPI)上显增量;快照策略 scored 占优。
